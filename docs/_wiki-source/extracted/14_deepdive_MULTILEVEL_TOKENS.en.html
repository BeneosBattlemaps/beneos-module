Before You Read

Here you'll find additional information that is not needed for using Beneos Battlemaps. All the sensible functions and settings have already been done for you in advance, and you can use everything immediately and intuitively. This deep dive is meant for those who want to add MLT  functions to their own maps or are just curious about how the module works.

Why Multilevel Tokens?

Multilevel Tokens (MLT) is a relatively old module but continues to work flawlessly. It's used to teleport tokens from one place to another. With MLT, we connect different maps together, allowing player and DM creatures to move independently from one map to another. A common question is, why do we use MLT when there are more modern modules that offer more options and also enable token teleportation? The answer lies in how MLT works. Unlike other modules, MLT doesn't use Foundry IDs but its own identifiers. This means, unlike (for example) Monks Active Tile Triggers (MATT), we can link two releases with MLT even though they are not part of the same pack. If "Pack A" is downloaded and then later "Pack B," they will automatically work together seamlessly without any extra effort. With MATT, this isn't possible. You'd need to download all maps as one giant release, or manually maintain all teleporters, which wouldn't be fun with several thousand scenes. Trust me :)

How MLT Works

Setting Up and Linking MLT Teleportation Zones MLT is very simple and error-free to use. Everything in MLT works through "Drawings," or shapes that we draw with the Drawing Tool in the left toolbar. We call these Drawings MLT fields.

With the active MLT module, in the settings of the drawn shape (Beneos always uses Rectangles), there's a new tab named "Multilevel." Here you will find all the important settings you need to set for each teleporter individually. Tip: You can simply copy the shapes with Ctrl+C and paste them onto other scenes.

  1. Here, you can determine whether the "Drawing," or rather the MLT field whose configuration you've opened, should be a Destination or a Source. MLT sends tokens from this field (Source) to another field (Destination). If "Out" is checked, you can teleport from this current MLT field to another. If "In" is active, you can teleport from another field into the current one. If both are checked, it goes both ways.

  2. The Teleport-Identifier is the core of MLT. You can enter any text here, but it's recommended to follow a logical structure. When a token is teleported from the current field, the Identifier indicates the destination. The token will be teleported to another field with the same Identifier. It's important that only two MLT fields have the same Identifier. If there are three or more fields with the same Identifier, a random selection is made, which could lead to unexpected errors. That means Source and Destination are defined by having the same Identifier.

    1. The naming convention for MLT at Beneos is as follows: ReleaseNumberA-MapNumberA_ReleaseNumberB-MapNumberB with leading zeros. The smaller number is always on the left. For example, it would be 76-04_76-05, or 64-04_76-01.

  3. With "Activate via Map Node," the MLT field remains inactive, even if tokens enter it. Only when a player clicks on a Journal Icon INSIDE the MLT field will MLT teleport the token from here to the Destination. This is useful because MLT fields are usually invisible, and players might accidentally change scenes without knowing. That's why we have placed a unique Journal Icon on all MLT fields. This Journal Icon (see Player Movement) serves only to signal to players that they can leave the map here and is available as a "button" if they wish to do so.

  4. Token Cloning is a tool I rarely use, but it can be a cool addition. Token Cloning means that the tokens IN another MLT field on the current MLT surface are displayed (or vice versa), but not teleported. If a token moves on Map A, it also moves on Map B. This is really cool, for example, if you're on the second floor of a house and can see the tokens active on the first floor. To use token cloning, the source and destination MLT fields must, as always, have the same Identifier. "Source" marks the field FROM which tokens are displayed (in the example, this would be the field on the first floor) and "Target" is the one where the tokens should be displayed (in the example, the one on the second floor).
