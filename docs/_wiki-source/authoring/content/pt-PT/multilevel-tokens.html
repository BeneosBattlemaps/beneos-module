Antes de leres: nada disto é necessário para usar os Beneos Battlemaps. Está tudo configurado por nós e funciona logo à partida. Este mergulho técnico é para quem quer adicionar funções do Multilevel Tokens aos seus próprios mapas, ou simplesmente tem curiosidade de saber como funciona.

O que o MLT faz

O Multilevel Tokens (MLT) é um módulo antigo que continua a funcionar na perfeição. Teleporta tokens de um lugar para outro, permitindo que as criaturas dos jogadores e do Mestre se movam de forma independente entre mapas. Porquê o MLT em vez de módulos mais recentes que também teleportam tokens? Pela forma como funciona. O MLT não usa IDs do Foundry, usa identificadores próprios. Isso significa que, ao contrário do Monk's Active Tiles, podemos ligar duas releases mesmo quando não fazem parte do mesmo pack. Descarrega o Pack A, mais tarde o Pack B, e eles funcionam juntos automaticamente. Com o Monk's Active Tiles terias de descarregar todos os mapas como uma release gigante ou manter cada teleportador à mão, o que não tem graça nenhuma em vários milhares de cenas. Confia em nós.

Como funciona o MLT

Tudo no MLT funciona através de desenhos, formas feitas com a Drawing Tool na barra de ferramentas esquerda. Chamamos-lhes campos MLT. Configurá-los e ligá-los é simples e à prova de erros.

Com o MLT ativo, as definições de uma forma desenhada (a Beneos usa sempre retângulos) ganham um novo separador chamado Multilevel. Define aqui tudo o que cada teleportador precisa, campo a campo. Dica: copia formas com Ctrl+C e cola-as noutras cenas.

  1. Origem ou destino. O MLT envia tokens de um campo de origem para um campo de destino. Marca Out para teleportar a partir deste campo. Marca In para teleportar para dentro dele. Marca ambos para viagens nos dois sentidos.
  2. Identificador de teleporte. O núcleo do MLT. Introduz qualquer texto, mas mantém-no lógico. Quando um token sai deste campo, o identificador aponta para o destino: o token vai para o outro campo com o mesmo identificador. Só dois campos devem partilhar um identificador. Com três ou mais, o MLT escolhe ao acaso, o que causa erros. Em resumo, origem e destino formam um par por partilharem um identificador.
    1. A convenção de nomes da Beneos é NumeroReleaseA-NumeroMapaA_NumeroReleaseB-NumeroMapaB com zeros à esquerda, número menor à esquerda. Por exemplo 76-04_76-05, ou 64-04_76-01.
  3. Ativar via Map Node. Com isto ligado, o campo fica inativo mesmo quando os tokens entram nele. Só um clique num ícone de journal dentro do campo aciona o teleporte. Isto importa porque os campos MLT são normalmente invisíveis e os jogadores podiam mudar de cena por acidente. Por isso colocamos um ícone de journal único em cada campo: diz aos jogadores que podem sair do mapa ali, e funciona como botão se assim o decidirem.
  4. Clonagem de tokens. Mais rara, mas engenhosa. A clonagem mostra os tokens de outro campo MLT na superfície atual (ou o inverso) sem os teleportar. Move um token no Mapa A e ele também se move no Mapa B. Ótimo para ver os tokens do primeiro andar enquanto estás no segundo. Os campos de origem e destino partilham o mesmo identificador, como sempre. Source é o campo de onde os tokens são exibidos (aqui, o primeiro andar), Target é onde eles aparecem (o segundo andar).

Segue os teus jogadores

Quando um jogador atravessa um teleportador, recebes um cartão de chat privado: quem se teleportou, para que cena, e um botão View Scene que te leva logo até ele. Acabou-se pensar para onde é que o grupo se enfiou. Vem ligado por predefinição; alterna-o em Notify GM on teleport nas definições do módulo se alguma vez o quiseres desligar.

Adicionar um som de teleporte

Queres que os jogadores oiçam algo quando usam um teleportador? Abre a Drawing Config do campo In, vai ao separador Multilevel e define um Teleport sound. Toca para os jogadores que viajam e para ti quando o teleporte dispara. Um pequeno toque que vende o momento.

Para saberes como isto se apresenta aos jogadores, vê Navegação dos jogadores. Para saltos de cena do lado do Mestre, vê POI Teleporter.
