Before you read: none of this is needed to use Beneos Battlemaps. Everything is set up for you and works out of the box. This deep dive is for anyone who wants to add Multilevel Tokens functions to their own maps, or is just curious how it works.

What MLT does

Multilevel Tokens (MLT) is an old module that still works flawlessly. It teleports tokens from one place to another, letting player and DM creatures move independently between maps. Why MLT over newer modules that also teleport tokens? Because of how it works. MLT does not use Foundry IDs, it uses its own identifiers. That means, unlike Monks Active Tiles, we can link two releases even when they are not part of the same pack. Download Pack A, then later Pack B, and they work together automatically. With Monks Active Tiles you would have to download every map as one giant release or maintain every teleporter by hand, which is no fun across several thousand scenes. Trust us.

How MLT works

Everything in MLT works through drawings, shapes made with the Drawing Tool in the left toolbar. We call them MLT fields. Setting up and linking them is simple and error-free.

With MLT active, a drawn shape's settings (Beneos always uses rectangles) gain a new tab called Multilevel. Set everything each teleporter needs here, per field. Tip: copy shapes with Ctrl+C and paste them onto other scenes.

  1. Source or destination. MLT sends tokens from a source field to a destination field. Check Out to teleport from this field. Check In to teleport into it. Check both for two-way travel.
  2. Teleport identifier. The core of MLT. Enter any text, but keep it logical. When a token leaves this field, the identifier points to the destination: the token goes to the other field with the same identifier. Only two fields should share an identifier. Three or more and MLT picks at random, which causes errors. In short, source and destination are paired by sharing an identifier.
    1. The Beneos naming convention is ReleaseNumberA-MapNumberA_ReleaseNumberB-MapNumberB with leading zeros, smaller number on the left. For example 76-04_76-05, or 64-04_76-01.
  3. Activate via Map Node. With this on, the field stays inactive even when tokens enter it. Only a click on a journal icon inside the field triggers the teleport. This matters because MLT fields are usually invisible and players might otherwise change scenes by accident. So we put a unique journal icon on every field: it tells players they can leave the map here, and acts as the button if they choose to.
  4. Token cloning. Rarer but neat. Cloning shows the tokens from another MLT field on the current surface (or the reverse) without teleporting them. Move a token on Map A and it also moves on Map B. Great for seeing first-floor tokens while you stand on the second. Source and destination fields share the same identifier as always. Source is the field tokens are displayed from (the first floor here), Target is where they show (the second floor).

Follow your players

When a player steps through a teleporter, you get a private chat card: who teleported, to which scene, and a View Scene button that jumps you right to them. No more wondering where the party wandered off to. It is on by default; toggle it under Notify GM on teleport in the module settings if you ever want it off.

Add a teleport sound

Want players to hear something when they use a teleporter? Open the In field's Drawing Config, go to the Multilevel tab, and set a Teleport sound. It plays for the players who travel and for you when the teleport fires. A small touch that sells the moment.
